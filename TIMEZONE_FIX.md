# Исправление проблемы с отображением игр в календаре

## Проблема
Запланированные игры отображались в календаре без учета часового пояса просматривающего.

## Причина
Приложение использовало `userTimezone` из профиля пользователя для всех операций с датами, но JavaScript Date объекты всегда интерпретируют компоненты (год, месяц, день, час) как время в timezone браузера, а не в `userTimezone`.

Это приводило к тому, что:
1. Пользователь выбирает время в `datetime-local` input (работает в timezone браузера)
2. Приложение пытается конвертировать это время в `userTimezone`
3. Если `userTimezone` != timezone браузера, возникает смещение

## Решение

### 1. Изменена функция `getUserTimezoneForAPI()` в `game-planer-front/src/services/api.js`:

```javascript
export const getUserTimezoneForAPI = () => {
  // ВАЖНО: Всегда используем timezone браузера для корректной работы Date объектов
  // currentUserTimezone используется только для отображения в UI
  return Intl.DateTimeFormat().resolvedOptions().timeZone
}
```

### 2. Упрощена функция `parseFromServer()` в `game-planer-front/src/utils/timezoneUtils.js`:

```javascript
export const parseFromServer = (serverDateStr, userTimezone) => {
  // Парсим ISO-8601 строку как UTC дату
  const utcDate = new Date(serverDateStr)
  
  // Просто возвращаем Date с правильным UTC timestamp
  // Браузер автоматически покажет время в своем timezone
  return utcDate
}
```

Теперь:
- Все операции с датами используют timezone браузера
- Date объекты имеют правильный UTC timestamp
- Браузер автоматически конвертирует время при отображении

## Влияние на функциональность

### Что работает корректно:
- ✅ Отображение игр в календаре
- ✅ Создание игр
- ✅ Запись на игры
- ✅ Отображение доступности игроков
- ✅ Выбор времени в планировщике

### Ограничения:
- Поле `timezone` в профиле пользователя теперь используется только для отображения в UI
- Все пользователи должны работать в timezone своего браузера
- Если пользователь хочет работать в другом timezone, ему нужно изменить timezone браузера

## Рекомендации для пользователей
Убедитесь, что timezone вашего браузера соответствует вашему реальному местоположению. Проверить можно так:
```javascript
console.log(Intl.DateTimeFormat().resolvedOptions().timeZone)
```

## Будущие улучшения
Для полной поддержки работы в произвольном timezone (не зависящем от браузера) потребуется:
1. Использовать библиотеку типа `date-fns-tz` или `luxon`
2. Хранить все даты как UTC timestamp
3. Конвертировать только при отображении
4. Использовать кастомные input компоненты вместо `datetime-local`
