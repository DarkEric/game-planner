# Автоматическая очистка устаревших данных

## Описание
Система автоматически удаляет устаревшие игры и временные слоты для предотвращения засорения базы данных.

## Функционал

### Что удаляется
- **Игры**: удаляются игры, которые закончились более N дней назад
- **Временные слоты**: удаляются слоты, которые начались более N дней назад

### Когда происходит очистка
По умолчанию очистка запускается **каждый день в 3:00 утра** по серверному времени.

## Конфигурация

### Переменные окружения

В файле `.env` или переменных окружения:

```bash
# Включить/выключить автоматическую очистку
CLEANUP_ENABLED=true

# Количество дней для хранения старых данных
# Например, 15 означает что данные старше 15 дней будут удалены
CLEANUP_RETENTION_DAYS=15

# Cron выражение для запуска очистки
# По умолчанию: каждый день в 3:00 утра
CLEANUP_CRON=0 0 3 * * ?
```

### Формат Cron выражения

Формат: `секунды минуты часы день месяц день_недели`

Примеры:
- `0 0 3 * * ?` - каждый день в 3:00 утра
- `0 0 2 * * ?` - каждый день в 2:00 утра
- `0 0 0 * * ?` - каждый день в полночь
- `0 0 4 * * SUN` - каждое воскресенье в 4:00 утра
- `0 0 3 1 * ?` - первого числа каждого месяца в 3:00 утра

### Настройки по умолчанию

Если переменные окружения не заданы, используются значения по умолчанию:
- `CLEANUP_ENABLED`: `true` (очистка включена)
- `CLEANUP_RETENTION_DAYS`: `15` (хранить данные 15 дней)
- `CLEANUP_CRON`: `0 0 3 * * ?` (запуск в 3:00 утра каждый день)

## Ручной запуск очистки

Для ручного запуска очистки (например, для тестирования) используйте API эндпоинт:

```bash
POST /api/admin/cleanup
```

Пример с curl:
```bash
curl -X POST http://localhost:8080/api/admin/cleanup \
  -H "Authorization: Bearer YOUR_JWT_TOKEN"
```

Ответ:
```json
{
  "status": "success",
  "message": "Cleanup completed successfully"
}
```

## Логирование

Сервис очистки записывает логи:
- Информация о запуске очистки
- Количество удаленных игр и временных слотов
- Ошибки при выполнении очистки

Пример логов:
```
INFO  CleanupService - Starting cleanup of old data (retention: 15 days)
DEBUG CleanupService - Deleted 5 old games (ended before 2025-11-01T00:00:00Z)
DEBUG CleanupService - Deleted 23 old time slots (started before 2025-11-01T00:00:00Z)
INFO  CleanupService - Cleanup completed: deleted 5 games and 23 time slots
```

## Отключение очистки

Чтобы отключить автоматическую очистку, установите:
```bash
CLEANUP_ENABLED=false
```

## Примеры использования

### Хранить данные 30 дней
```bash
CLEANUP_RETENTION_DAYS=30
```

### Запускать очистку каждую неделю
```bash
CLEANUP_CRON=0 0 3 * * SUN
```

### Запускать очистку каждый час
```bash
CLEANUP_CRON=0 0 * * * ?
```

### Запускать очистку каждую минуту (для тестирования)
```bash
CLEANUP_CRON=0 * * * * ?
```

## Технические детали

- Очистка выполняется в транзакции
- При удалении игры автоматически удаляются связи с участниками (через каскадное удаление)
- Временные слоты удаляются независимо от игр
- Если очистка отключена, задача не выполняется
- Ошибки при очистке логируются, но не останавливают приложение

## Отладка

### Проверить конфигурацию очистки

```bash
GET /api/admin/cleanup/info
```

Пример с curl:
```bash
curl http://localhost:8080/api/admin/cleanup/info \
  -H "Authorization: Bearer YOUR_JWT_TOKEN"
```

Ответ:
```json
{
  "enabled": true,
  "retentionDays": 1,
  "cronExpression": "0 * * * * ?",
  "cutoffDate": "2025-11-15T10:00:00Z",
  "oldGamesCount": 5,
  "oldTimeSlotsCount": 23
}
```

### Проверить логи

При запуске приложения должны появиться логи:
```
INFO  CleanupService - CleanupService initialized:
INFO  CleanupService -   - Enabled: true
INFO  CleanupService -   - Retention days: 1
INFO  CleanupService -   - Cron expression: 0 * * * * ?
```

При выполнении очистки:
```
INFO  CleanupService - Starting cleanup of old data (retention: 1 days)
DEBUG CleanupService - Deleted 5 old games (ended before 2025-11-15T10:00:00Z)
DEBUG CleanupService - Deleted 23 old time slots (started before 2025-11-15T10:00:00Z)
INFO  CleanupService - Cleanup completed: deleted 5 games and 23 time slots
```

### Частые проблемы

1. **Очистка не запускается**
   - Проверьте, что `@EnableScheduling` добавлен в главный класс приложения
   - Проверьте, что переменные окружения передаются в Docker контейнер
   - Проверьте логи при запуске приложения

2. **Неправильный cron**
   - Формат: `секунды минуты часы день месяц день_недели`
   - Для каждой минуты: `0 * * * * ?`
   - Для каждого часа: `0 0 * * * ?`
   - Для каждого дня в 3:00: `0 0 3 * * ?`

3. **Данные не удаляются**
   - Проверьте `CLEANUP_RETENTION_DAYS` - возможно, данные еще не старые
   - Используйте `/api/admin/cleanup/info` для проверки количества данных для удаления
   - Запустите очистку вручную через `/api/admin/cleanup`

## Мониторинг

Рекомендуется настроить мониторинг логов для отслеживания:
- Регулярности выполнения очистки
- Количества удаляемых записей
- Ошибок при выполнении

## Безопасность

⚠️ **Важно**: Эндпоинт `/api/admin/cleanup` в текущей версии доступен всем авторизованным пользователям. В production рекомендуется добавить проверку прав администратора.

## Восстановление данных

⚠️ **Внимание**: Удаленные данные не подлежат восстановлению. Убедитесь, что настройки `CLEANUP_RETENTION_DAYS` соответствуют вашим требованиям перед включением очистки.

Рекомендуется:
- Настроить регулярное резервное копирование базы данных
- Установить достаточный период хранения (например, 30-60 дней)
- Протестировать очистку на тестовом окружении перед production
